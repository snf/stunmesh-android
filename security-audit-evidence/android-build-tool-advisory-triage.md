# Android build-tool advisory triage

Checked 2026-09-13 against the exact resolved build classpath from the isolated offline `buildEnvironment` run ([dependency tree](android-build-environment.txt)), the [OSV coordinate scan](android-maven-osv-scan.json), and the [GitHub advisory metadata snapshot](android-build-tool-advisory-primary-sources.json). All seven advisories concern six **build-tool** components; none is in the resolved release-runtime graph. The cached JARs matched publisher bytes in [the artifact comparison](android-build-tool-artifact-published-sha256.json). That verifies distribution consistency, not absence of malicious code or exploitability.

The Kotlin advisory's headline is broad, but its [fix commit](https://github.com/JetBrains/kotlin/commit/bf51df665b458fda7c3eaf436c4d88dc119d7ec6) identifies the deserializer as KAPT incremental caching, which this project does not use. `actions/setup-java@v5` [caches Gradle dependencies and wrapper files](https://github.com/actions/setup-java/blob/v5/README.md), and its [source path list](https://github.com/actions/setup-java/blob/v5/src/cache.ts) includes `~/.gradle/caches`; that alone does not establish that the vulnerable KAPT cache is created or restored. GitHub's [cache access restrictions](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching) also mean a forked `pull_request` cache is scoped to that PR's merge ref and cannot ordinarily be restored by a release-tag run. The tag can read caches from its own scope and the default branch. Thus this advisory is **not** evidence that any external PR author can poison this release. The separate demonstrated tag-shell injection (A-16) remains a direct release blocker regardless of caching.

These are advisory-to-site assessments, not a complete audit of AGP/Kotlin/Bouncy Castle internals. The release build and unit tests passed, but the vulnerable methods were not dynamically instrumented or fuzzed. No affected dependency is known to ship in the Android app runtime graph.
