Material3 OutlinedTextField.kt (String value overload, lines 385-386) declares
visualTransformation and keyboardOptions as separate parameters, with
keyboardOptions defaulting to KeyboardOptions.Default. It passes both
unchanged to BasicTextField (lines 426-434).

Foundation KeyboardOptions.kt: Default = KeyboardOptions() (line 69), whose
keyboardType is Unspecified and autoCorrectEnabled is null (lines 57-60).
Its toImeOptions uses keyboardTypeOrDefault = KeyboardType.Text (line 167)
and autoCorrectOrDefault = true (line 159). BasicTextField.kt passes those
options to CoreTextField at lines 790/921. CoreTextField.kt treats
PasswordVisualTransformation as an isPassword semantics flag (line 475),
but does not change the IME options from keyboardOptions in that path.
UI TextInputServiceAndroid.android.kt maps KeyboardType.Text to
InputType.TYPE_CLASS_TEXT and KeyboardType.Password to
TYPE_CLASS_TEXT | TYPE_TEXT_VARIATION_PASSWORD (lines 513-526).

Thus display masking alone does not send a password keyboard type to the IME.
This is source/platform evidence, not a measured leak on an Android device.
The Android keyboard is always an input trust dependency and may ignore hints;
Password keyboard options are a risk reduction, not a complete barrier
against a malicious keyboard.
